#### `Optional` showHigh

```ts
showHigh?: boolean = false
```

Defines whether or not a plotline for the highest value in view should be displayed on the chart.

If set to `true`, a horizontal plotline will be shown at the highest value currently visible in the chart view.

Can be toggled globally in the Global-Settings Menu (TopToolbar).

##### Default Value

`false`

#### `Optional` showHighLow

```ts
showHighLow?: boolean = false
```

Defines whether or not a plotline for the lowest and hightest value in view should be displayed on the chart.

If set to `true`, a horizontal plotline will be shown at the lowest and highest value currently visible in the chart view.

Can be toggled globally in the Global-Settings Menu (TopToolbar).

### Indicators

#### `Optional` indicatorColors

```ts
indicatorColors?: string[]
```

Defines the colors for each [ChartWidgetOptions.indicators](#indicators) Chart-Series.

If set, this option overwrites the indicator-colors set by stylesheets!

The first color string correlates to the first indicator series in the chart.
When the last color of the indicatorColors-list has been taken, the next indicator restarts with the first color.

Expects a valid CSS color format string.

##### Example

```css
'black', '#ffffff', 'rgb(2555,255,255)', 'rgba(255,255,255,1)', 'hsl(120,100%,50%)', 'hsla(120,100%,50%,0.3)'
```

##### Default Value

`undefined`

#### `Optional` indicators

```ts
indicators?: ChartIndicatorSettings[]
```

Defines the initial list of indicators that are to be added to the initial list of [ChartWidgetOptions.instruments](#instruments).

Allows for both simple & complex indicator configurations.

The linkedTo property expects an index of the instruments option.
Otherwise the indicator will be added to the main-instrument.

##### See

[ChartIndicatorSettings](../WTK.ChartIndicatorSettings.md) | [IndicatorType](../WTK.IndicatorType.md)

##### Default Value

`undefined`

#### `Optional` indicatorsBasedOnResolution

Defines if the indicator data should be based on the current resolution or not.

In (Highcharts) technical terms: use grouped data for indicator calculation: no for `false` and yes for ` true`.

##### Default Value

`false`

### Instrument

#### `Optional` adjustDividends

```ts
adjustDividends?: boolean = false
```

Defines whether or not distribution of dividends should initially be taken into account
when requesting Chart-Data for Instruments.

Can be toggled globally in the Global-Settings Menu (TopToolbar)

- Can be toggled for each instrument in its Instrument-Settings Menu (Chart-Legend)

##### Default Value

`false`

#### `Optional` adjustSplits

```ts
adjustSplits?: boolean = true
```

Defines whether or not splits should initially be taken into account
when requesting Chart-Data for Instruments.

A split is an administrative and artificial mean by the corporation to change the ratio
between its share’s value and the amount.
If the value is halfed, then the amount of shares will be doubled.

The opposite is called reverse-split.

Can be toggled globally in the Global-Settings Menu (TopToolbar)

- Can be toggled for a single instrument in its Instrument-Settings Menu (Chart-Legend)

##### Default Value

`true`

#### `Optional` calendarFeeds

```ts
calendarFeeds?: number[] = []
```

Defines which Feeds should be taken to request Corporate Calendar Events from.
Acts as a filter.

If set to `[]`, undefined or ` null`, no filter is applied. Data from all sources are being requested.

##### Default Value

`[]`

### Instrument-Header

#### `Optional` callbackChartFields

```ts
callbackChartFields?: (chartFields: ChartFields) => any
```

Allows for a callback to receive calculated data (chartFields) from the instrumentHeader.

Available fields: `absChange, pctChange, currentStartDate, currentEndDate, currentPeriod`

##### Type Declaration

- (chartFields: ChartFields): any

  ##### Parameters

  - chartFields: [ChartFields](../WTK.ChartFields.md)

  ##### Returns any

##### Example

```ts
opts.callbackChartFields = (chartFields) => {
  chartFields?.pctChange?.observe({
    valueUpdated: (value) => {
      console.log("chartFields - calculated pctChange", value);
    },
  });
};
```

##### Default Value

`undefined`

#### `Optional` instrumentHeader

```ts
instrumentHeader?: InstrumentHeaderOptions = ...
```

Defines whether or not the InstrumentHeader should be present, providing additional
information about the chart and the Main-Instrument.

The InstrumentHeader is located to the very right side of the TopToolbar and consists of
Main-Instrument related Chart- and SymbolFields (ChartFields, QuoteFields).

You may configure the displayed fields based on the symbolBaseType later on in the
[instrumentHeaderChartFields](#instrumentheaderchartfields) and [instrumentHeaderQuoteFields](#instrumentheaderquotefields) options.

##### See

[InstrumentHeaderOptions](../WTK.InstrumentHeaderOptions.md) | [SymbolBaseType](../WTK.SymbolBaseType.md)

##### Default Value

`{ chartFields: true, quoteFields: true, symbolBaseType: SymbolBaseType.CLASSIFICATION }`

#### `Optional` instrumentHeaderChartFields

```ts
instrumentHeaderChartFields?: ChartFieldList = ...
```

Defines which ChartFields should be displayed depending on the [SymbolBaseType](../WTK.SymbolBaseType.md) of the active Main-Instrument.

Enables different configurations by nesting the fields them below a [SymbolBaseType](../WTK.SymbolBaseType.md) property.

ChartFields are either read directly from widgets state or the chart instance.

Currently supported fields: `'absChange'`, `'pctChange'`, `'currentPeriod'`, `'lastValidDate'`, `'lastValidTime'`

##### See

[ChartFieldList](../WTK.ChartFieldList.md) | [ChartField](../WTK.ChartField.md)

##### Default Value

`[{ name: 'currentPeriod', label: false }, { name: 'absChange', label: false, enableStatusColors: true }, { name: 'pctChange', label: false, enableStatusColors: true, }]`

#### `Optional` instrumentHeaderQuoteFields

```ts
instrumentHeaderQuoteFields?: QuoteFieldList = ...
```

Defines which QuoteFields (SymbolFields) should be displayed depending on the [SymbolBaseType](../WTK.SymbolBaseType.md) of the active Main-Instrument.

You may use different field configurations by nesting the fields below a SymbolType/-Classification property.

1. Available types in case [SymbolBaseType.CLASSIFICATION](../WTK.SymbolBaseType.md#classification) is used as `symbolBaseType` in [instrumentHeader](#instrumentheader):
  [InfrontSDK.SymbolClassification](../../SDK/SDK.InfrontSDK.SymbolClassification.md)
2. Available types in case [SymbolBaseType.TYPE](../WTK.SymbolBaseType.md#type) is used as `symbolBaseType` in [instrumentHeader](#instrumentheader):
  [InfrontSDK.SymbolType](../../SDK/SDK.InfrontSDK.SymbolType.md)

##### See

[QuoteFieldList](../WTK.QuoteFieldList.md) | [QuoteField](../WTK.QuoteField.md) | [BlinkType](../WTK.BlinkType.md) | [BlinkDuration](../WTK.BlinkDuration.md)

##### Default Value

`object`

#### `Optional` redrawTimeout

```ts
redrawTimeout?: number = 300
```

Defines the milliseconds of the timeout between chart redraws.

A chart redraw only updates the existing instance with new options.

This throttle helps reducing CPU load on constant chart redraws on high-frequency traded multi-instrument streaming.

Redraws are being triggered by following events:

- streaming updates on instruments
- period zooming via navigator and mousewheel-scrolling
- toggling `prevClose` in the Global-Settings when on a 1 day intraday period
- removing an instrument, indicator

##### Remarks

- Needs to be at least `50`, otherwise fallbacks to good compromise `300`.

##### Default Value

`300`

#### `Optional` reflowTimeout

```ts
reflowTimeout?: number = 50
```

Defines the milliseconds of the timeout before the chart reflows.

A chart reflow does not update any options but instead triggers recalculations of the
elements positions and dimensions.

Reflow is being triggered by the following events:

- resizing the Chart-Widget container

##### Remarks

- Needs to be at least `5`,otherwise fallbacks to good compromise `50`.
- Smaller values like 5-10ms can be set in WT5-alike systems for window-resize to be smoother!

##### Default Value

`50`

#### `Optional` updateTimeout

```ts
updateTimeout?: number = 300
```

Defines the milliseconds of the timeout between chart updates and re-creations.

A chart re-creation is one of the most stressful methods for the widget.
The chart instance is discarded and re-instantiated.

The idea behind this is to collect multiple changes at once and then update them all
in a single chart re-creation after the timeout is finished.

Updates are being triggered by following events:

- changing instruments (adding, replacing)
- changing indicators
- changing period (if new period is not subset of the current one)
- changing resolution (only with vwbp indicator present)
- changing chartType
- changing the currency
- toggling the cursorEventsEnabled (only with vwbp indicator present)
- doing any change in the Global-Settings, Instrument-Settings and Indicator-Settings Menu
- selecting a template
- calling setMainPerformance from the widgets reference

##### Remarks

- Needs to be at least `50`, otherwise fallbacks to good compromise `300`.

##### Default Value

`300`

### Periods

#### `Optional` navigatorScrollFactor

```ts
navigatorScrollFactor?: number = 0.2
```

Defines the relative scroll factor when using the mouse wheel to scroll through the period
while being in a zoomed period state.

As a basis it takes the currently zoomed interval and multiplies it by the set factor.

A factor of `1` will basically set the new start-date (xAxis extreme on the left, “min”)
to the previous end-date (xAxis extreme on the right, “max”).

It’s advised to only use values between 0 and equal or below 1 `(0 < x <= 1)`.

Everything beyond a factor of 1 will cause the scrolling to skip time intervals.
