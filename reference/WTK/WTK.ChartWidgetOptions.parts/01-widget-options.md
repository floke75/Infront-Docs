### Cache

#### `Optional` caching

```ts
caching?: boolean = false
```

Defines whether or not caching of instrument Chart-Data is initially enabled.

Speeds up loading times and reduces network load when switching instruments that have been previously added.

Criteria for a valid instrument Chart-Data cache entry:

- Same instrument (feed, ticker)
- intraday/historical
- shorter or at least equal period, end-date not older than a single resolution step or 4 hours
- resolution (does not matter on historical period as it’s always 1D)
- Chart-Data Type (open, high, low, close, bid, ask)
- currency
- adjustDividends/adjustSplits

The cache is stored in the runtime memory and cleared upon reloading the page.

##### Remarks

If the instrument receives a streaming update, the expiration time of the cache’s entry is also refreshed.

##### Default Value

`false`

### Chart-Axis

#### `Optional` areaStacking

```ts
areaStacking?: "percent" | "normal"
```

Enables area stacking for area-type charts. When set, each series is drawn as a filled
area stacked on top of the previous one.

- `'normal'`: stacked by absolute value; Y-axis shows the cumulative sum of all series.
- `'percent'`: stacked as a proportion of total; Y-axis is always 0–100%.
- `undefined` (default): stacking is disabled.

**Restrictions - the following are enforced automatically when stacking is active:**

- All instrument series are rendered as `area` type regardless of ` chartType`.
- Ordinate scaling is forced to `ABSOLUTE` (` compare` mode is incompatible with stacking).
- The Y-axis minimum is forced to `0`; for `'percent'` the maximum is forced to `100`.
- Streaming updates are suppressed (push data cannot be stacked correctly in real time).
- Data grouping (resolution aggregation) is disabled per series.
- The Highcharts navigator series inherits no stacking to prevent display artefacts.

**Recommendations for correct visual output:**

- Use at least two instruments; stacking a single series has no visual meaning.
- All instruments should be traded in the same currency so that absolute values are comparable.
- Disable the opposite ordinate (`showOppositeOrdinate: false`); a relative left axis is
  meaningless when Y values are forced to absolute stacked totals.

Can also be changed at runtime via ChartWidget.setAreaStacking.

##### Default Value

`undefined`

#### `Optional` onPointMouseOver

```ts
onPointMouseOver?: (
    point: Readonly<HighchartsPointWithOhlc>,
    extraData: readonly ChartHoverSeriesValue[],
) => void
```

Callback for mouse hover on a data point in the chart.

The first parameter is the Highcharts.Point object of the actually-hovered series (extended
with `open`/` high`/` low`/` close` when the instrument has OHLC data).

The second parameter, `extraData`, is the same additional information (with the same
special-casing) shown in the chart's tooltip for the hovered timestamp - one entry per series
currently shown on the chart (including the hovered one, flagged via `isHoveredSeries`), each
with its own `timestamp`, value/OHLC, volume, turnover and pct-change vs. the previous point -
so it can be consumed programmatically without having to parse or duplicate the tooltip's own
formatting logic. Series other than the hovered one are looked up by nearest timestamp (a binary
search, not a linear scan - cheap even with many data points) since different instruments/feeds
never share exact timestamps - hence each entry carries its OWN `timestamp`, which will generally
differ slightly from `point.x` and from other entries' ` timestamp`. ` extraData` is only computed
(a handful of lookups per hover, one set per series) when this callback is actually set.

##### Type Declaration

- (point: Readonly<HighchartsPointWithOhlc>,    extraData:

  ```ts
  readonly
  ```

  ChartHoverSeriesValue[],): void

  ##### Parameters

  - point: Readonly<HighchartsPointWithOhlc>
  - extraData: readonly [ChartHoverSeriesValue](../WTK.ChartHoverSeriesValue.md)[]

  ##### Returns void

##### Example

```ts
opts.onPointMouseOver = (point, extraData) => {
  console.log("hovered point", point.x, point.y, point.open, point.high, point.low, point.close);

  extraData.forEach((series) => {
    console.log(
      series.isHoveredSeries ? "hovered series" : "other series",
      "name:", series.name,
      "seriesId:", series.seriesId,
      "timestamp:", series.timestamp,
      "value:", series.value,
      "open:", series.open,
      "high:", series.high,
      "low:", series.low,
      "close:", series.close,
      "volume:", series.volume,
      "turnover:", series.turnover,
      "pctChange:", series.pctChange,
    );
  });
};
```

#### `Optional` adjustSplits

```ts

```

Defines whether or not splits should initially be taken into account
when requesting Chart-Data for Instruments.

A split is an administrative and artificial mean by the corporation to change the ratio
between its share’s value and the amount.
If the value is halfed, then the amount of shares will be doubled.

#### `Optional` adjustStartDate

```ts
adjustStartDate?: boolean = true
```

Defines whether or not an extra trading day should be prepend to the start-date.

This option only effects history data.

If set to `false` the start-date (first day displayed in chart) is calculated by exactly using the selected period

Example for 1 year period: 11.10.2022 - 11.10.2023

If set to `true` the calculation is the same, but the last valid trading-day before the calculated start-date will be used as start-date.

Example for 1 year period: 07.10.2022 - 11.10.2023

This adjusted start-date makes sense to have the proper performances shown as values on the chart axes.

##### Default Value

`true`

#### `Optional` caching

```ts
caching?: boolean = false
```

Defines whether or not caching of instrument Chart-Data is initially enabled.

Speeds up loading times and reduces network load when switching instruments that have been previously added.

Criteria for a valid instrument Chart-Data cache entry:

- Same instrument (feed, ticker)
- intraday/historical
- shorter or at least equal period, end-date not older than a single resolution step or 4 hours
- resolution (does not matter on historical period as it’s always 1D)
- Chart-Data Type (open, high, low, close, bid, ask)
- currency
- adjustDividends/adjustSplits

The cache is stored in the runtime memory and cleared upon reloading the page.

##### Remarks

If the instrument receives a streaming update, the expiration time of the cache’s entry is also refreshed.

`false`

#### `Optional` indicatorsBasedOnResolution

```ts
indicatorsBasedOnResolution?: boolean = false
```

Defines if the indicator data should be based on the current resolution or not.

In (Highcharts) technical terms: use grouped data for indicator calculation: no for `false` and yes for ` true`.

##### Default Value

`false`

#### `Optional` loadIntradayIndicatorsExtraData

```ts
loadIntradayIndicatorsExtraData?: boolean = false
```

Defines for intraday charts, where display of indicators depending on a time period starts in the chart.

This option only effects intraday charts. Historical charts always loads extra data for indicators!

If set to `false`, indicators with a period will start after the period, in the middle of the chart.

If set to `true`, extra chart data is loaded, depending on the maximum period setting used by currently configured indicators.

##### Default Value

`false`

#### `Optional` mainDataType

```ts
mainDataType?: SelectableDataType = SelectableDataType.AUTO
```

Defines the main instrument's series-data-type.

Can be changed for a single instrument in its Instrument-Settings Menu (Chart-Legend).

mainDataType can be one of the following:

- 'automatic': internal rule-based selection of data-type
- 'open': chart shows instrument's OPEN price data
- 'high': chart shows instrument's HIGH price data
- 'low': chart shows instrument's LOW price data
- 'close': chart shows instrument's CLOSE price data
- 'bid': chart shows instrument's BID price data
- 'ask': chart shows instrument's ASK price data
- 'mid': chart shows instrument's MID price data
- 'bidask': used for instrument duplication into BID and ASK series
- 'performance': used for instrument duplication into series with/without dividends

##### See

[ChartType](../WTK.ChartType.md)

##### Default Value

`'auto'`
