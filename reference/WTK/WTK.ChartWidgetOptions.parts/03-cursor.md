### Cursor

#### `Optional` cursorEventsEnabled

```ts
cursorEventsEnabled?: boolean = true
```

Defines whether or not the cursor events (mouseover/hover) are initially enabled or not.

If set to `false`, all effects will be disabled (No data point highlighting,
vertical/horizontal line, moving series labels).

Can be toggled by clicking the cursor events button (TopToolbar).

##### Default Value

`true`

#### `Optional` cursorSnapX

```ts
cursorSnapX?: boolean = true
```

Defines whether or not the vertical line of the cursor events (mouseover/hover)
initially snaps to the nearest data point.

Can be toggled in the Global-Settings Menu (TopToolbar).

##### Default Value

`true`

#### `Optional` cursorSnapY

```ts
cursorSnapY?: boolean = false
```

Defines whether or not the horizontal line of the cursor events (mouseover/hover)
initially snaps to the nearest data point.

Can be toggled in the Global-Settings Menu (TopToolbar).

##### Default Value

`false`

#### `Optional` cursorType

```ts
cursorType?: CursorType = CursorType.CROSSHAIR
```

Defines the cursor type initially which is responsible for different mouseover/hover effects on the chart.

Can be changed in the Global-Settings Menu (TopToolbar).

##### See

[CursorType](../WTK.CursorType.md)

##### Default Value

`'crosshair'`

#### `Optional` pulseTrackLabelColor

```ts
pulseTrackLabelColor?: string
```

Optional color for the [showPulseTrackLine](#showpulsetrackline) label text when the change is positive (or
exactly zero). If set, overrides the default color.

##### Default Value

```ts
undefined
```

#### `Optional` pulseTrackLabelFontSize

```ts
pulseTrackLabelFontSize?: string
```

Optional font-size for the [showPulseTrackLine](#showpulsetrackline) label. If set, overrides the default font-size.

##### Default Value

```ts
undefined
```

#### `Optional` pulseTrackLabelNegativeColor

```ts
pulseTrackLabelNegativeColor?: string
```

Optional color for the [showPulseTrackLine](#showpulsetrackline) label text when the change is negative. If
set, overrides the default color.

##### Default Value

```ts
undefined
```

#### `Optional` pulseTrackLineColor

```ts
pulseTrackLineColor?: string
```

##### Default Value

```ts
undefined
```

#### `Optional` pulseTrackLineNegativeColor

```ts
pulseTrackLineNegativeColor?: string
```

```ts

```

#### `Optional` pulseTrackLineOptions

```ts
pulseTrackLineOptions?: ChartPulseTrackLineOptions
```

Optional object to customize the [showPulseTrackLine](#showpulsetrackline) line. Properties (width, dashStyle,
zIndex) will overwrite defaults.

##### Default Value

```ts
undefined
```

#### `Optional` pulseTrackType

```ts
pulseTrackType?: PulseTrackType = PulseTrackType.PERCENT
```

Defines whether the [showPulseTrackLine](#showpulsetrackline) label shows the raw price change or the
percentage change between the hovered point and the current (last visible) price.

##### See

[showPulseTrackLine](#showpulsetrackline)

##### Default Value

`PulseTrackType.PERCENT`

#### `Optional` pulseTrackUseSeriesColor

```ts
pulseTrackUseSeriesColor?: boolean = false
```

Defines whether the [showPulseTrackLine](#showpulsetrackline) line uses the hovered series' own color instead
of the pos/neg colors, when more than one series is active. With a single series this has no
effect (the pos/neg colors are used, since there is nothing to tell apart).

##### Default Value

`false`

#### `Optional` showPulseTrackLine

```ts
showPulseTrackLine?: boolean = false
```

Defines whether or not a dashed, arrow-tipped line is drawn from the currently-hovered point on
a series to that series' current price (the last VISIBLE point - i.e. it follows the visible
navigator/scrollbar range, not necessarily the true last data point overall - at the right edge
of the plot area, same reference the Chart-Series label uses). The line updates live as the last
visible price streams in.

##### Default Value

`false`

### Decimals

#### `Optional` crosshairLabelDecimals

```ts
crosshairLabelDecimals?: number
```

Defines the fixed number of decimals to be used on the crosshairLabel (part of the mainYAxis).

##### See

[crosshairLabelDecimalsPercentage](#crosshairlabeldecimalspercentage) | [crosshairLabelDecimalsCallback](#crosshairlabeldecimalscallback)

##### Default Value

`undefined`

#### `Optional` crosshairLabelDecimalsCallback

```ts
crosshairLabelDecimalsCallback?: DecimalsCallback
```

A callback that provides the user with the to be formatted crosshairLabel values and an indication if it's a pct value or not.
Enables customers to write their own decimals handling logic.
Expects the number of decimals to be returned which will then be applied before displaying the value in the crosshairLabel.

Has a low priority in comparison with the other decimals options:
In case the corresponding options [crosshairLabelDecimals](#crosshairlabeldecimals) or [crosshairLabelDecimalsPercentage](#crosshairlabeldecimalspercentage) are set, they will be used instead of this callback.

##### See

[crosshairLabelDecimals](#crosshairlabeldecimals) | [crosshairLabelDecimalsPercentage](#crosshairlabeldecimalspercentage)

##### Default Value

`undefined`

##### Param: value

the value to be displayed (and decimals applied to)

##### Param: isPercentage

indicates whether or not it's an absolute or a pct value

##### Returns

The amount of decimals to display the value with.

#### `Optional` adjustSplits

```ts
adjustSplits?: boolean = true
```

Defines whether or not splits should initially be taken into account
when requesting Chart-Data for Instruments.

A split is an administrative and artificial mean by the corporation to change the ratio
between its share’s value and the amount.
If the value is halfed, then the amount of shares will be doubled.

The opposite is called reverse-split.

Can be toggled globally in the Global-Settings Menu (TopToolbar)

- Can be toggled for a single instrument in its Instrument-Settings Menu (Chart-Legend)

##### Default Value

`true`

#### `Optional` adjustStartDate

```ts
adjustStartDate?: boolean = true
```

Defines whether or not an extra trading day should be prepend to the start-date.

This option only effects history data.

If set to `false` the start-date (first day displayed in chart) is calculated by exactly using the selected period

Example for 1 year period: 11.10.2022 - 11.10.2023

If set to `true` the calculation is the same, but the last valid trading-day before the calculated start-date will be used as start-date.

Example for 1 year period: 07.10.2022 - 11.10.2023

This adjusted start-date makes sense to have the proper performances shown as values on the chart axes.

##### Default Value

`true`

#### `Optional` caching

```ts
caching?: boolean = false
```

Defines whether or not caching of instrument Chart-Data is initially enabled.

Speeds up loading times and reduces network load when switching instruments that have been previously added.

Criteria for a valid instrument Chart-Data cache entry:

- Same instrument (feed, ticker)
- intraday/historical
- shorter or at least equal period, end-date not older than a single resolution step or 4 hours
- resolution (does not matter on historical period as it’s always 1D)
- Chart-Data Type (open, high, low, close, bid, ask)
- currency
- adjustDividends/adjustSplits

The cache is stored in the runtime memory and cleared upon reloading the page.

##### Remarks

If the instrument receives a streaming update, the expiration time of the cache’s entry is also refreshed.

##### Default Value

`false`

